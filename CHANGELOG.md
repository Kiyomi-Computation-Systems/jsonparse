# Changelog

All notable changes to jsonparse are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
uses [semantic versioning](https://semver.org/spec/v2.0.0.html): before 1.0,
any release may change the API, and a new minor version comes with a new
byte-machine runtime ABI or a move to a new byte-machine 0.x, such as from
`^0.8.0` to `^0.9.0`.

## [0.2.0] - 2026-11-13

**Faster at building trees of numbers, and at long runs of ASCII in
strings.** The API is the same as 0.1.0's. The parser is now generated by
byte-machine 0.9.0, still at runtime ABI 9, and jsonparse depends on
`^0.9.0`. The package isn't on Akku yet. It goes there once the libraries
an application might install beside it, such as chez-http-server, accept
byte-machine 0.9 too.

### Added

- **`read-json`'s docs say what it does on a port whose bytes are still
  coming,** such as a request body. It reads 16 KiB at a time, so bad
  input is refused only once the 16 KiB that hold the error have come, or
  the port has ended. What the port itself raises passes through as it was
  raised. Tests hold both. `read-json` itself is unchanged.
- **Benchmarks.** `make bench` times jsonparse against yajl and eleven
  other JSON parsers on eight test files, five public and three generated,
  and `make bench-callbacks` splits what a callback costs. `README.org`
  says how to run them.

### Changed

- **Files full of numbers read as a tree in up to 25% less time.** A
  number of up to 18 digits is now converted straight from its bytes, with
  no string made in between: an integer in `flonum` and `exact` modes, and
  a decimal with a small exponent in `flonum` mode. As a tree, `ints-40k`
  and `canada` take 21% to 25% less time, and files with fewer numbers
  gain less. Events don't change. Values, stops and errors are the same.
- **Long runs of ASCII text in strings parse in about 40% less time.** The
  parser is now generated by byte-machine 0.9.0, which reads a run of plain
  bytes in a tight loop. `gsoc-2018.json`, whose strings are long and ASCII,
  takes about 40% less time with events and 28% less as a tree. In both,
  other files change by up to about 7% either way, which is about as much
  as a change in code layout alone moves them. Results, offsets and errors
  are the same.
- **jsonparse now depends on byte-machine `^0.9.0`.** byte-machine's
  runtime is unchanged, and its runtime ABI is still 9. Akku installs one
  byte-machine per project, so jsonparse can be installed beside another
  library that uses byte-machine only once that library accepts 0.9 too.

## [0.1.0] - 2026-11-08

**The first release: a strict, resumable JSON parser for R6RS Scheme, with
a docs site.** Its parser is generated by byte-machine 0.8.0, runtime ABI 9,
and the libraries import only `(rnrs)` and byte-machine's runtime. It is
packaged for Akku, and `make check-akku` installs the package as a consumer
would and checks what lands.

### Added

- **`(jsonparse easy)`:** one import to read and write whole documents.
  - `string->json`, `bytevector->json` and `read-json` read a string, UTF-8
    bytes or a binary port into plain Scheme values: objects as alists in
    document order, or hashtables; arrays as vectors; `null` as the symbol
    `null`, or a value of your choosing.
  - `json->string`, `json->bytevector` and `write-json` write compact or
    indented JSON. A value JSON can't express is refused before a byte is
    written.
  - `json-ref` looks inside a value, `json-null?` tests for null, and
    `json=?` compares two values as JSON.
  - Bad input raises a `&json-error` with a reason, such as
    `unexpected-byte`, and an offset.
- **Streams of values:** JSON Lines and NDJSON, RFC 7464 records, and values
  separated by whitespace, read and written record by record. A bad record
  stops the stream, or is reported and skipped.
- **Numbers:** an integer reads as an exact integer and any other number as
  a flonum, or every number exact, or as its text. In the first two modes a
  digit limit, 1,000 by default, bounds the work a number can cost; the text
  mode keeps every digit.
- **Input in pieces:** a push parser that calls your procedures and never
  raises on bad input; a builder that makes values; a reader of streams;
  and a writer to binary ports. Input split anywhere gives the same result.
  Parsing to events allocates nothing per byte, value or container.
- **Limits:** a nesting depth limit, 512 by default.
- **Conformance:** every `y_` case of JSONTestSuite is accepted and every
  `n_` case refused. yajl's and SRFI 180's cases pass, nativejson-benchmark's
  27 round-trip files come back byte for byte, and 3,353 numbers from
  parse-number-fxx-test-data read as exactly their float64 bits. Each is
  read with a digit limit past its length, and an integer text with `e0`
  after it, since a bare integer reads exact.
- **Documentation:** guides to the libraries, an API reference, and a site
  at <https://kiyomi-computation-systems.github.io/jsonparse/>.
