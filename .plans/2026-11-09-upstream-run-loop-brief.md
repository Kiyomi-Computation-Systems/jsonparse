# Upstream brief: a state's loop back to itself compiles to a tight loop

- **Date:** 2026-11-09
- **From:** jsonparse, slice 14 (plan M3, lever 2; ADR-0023, ADR-0025)
- **To:** byte-machine, at `main` `3c56875` (v0.8.0 and five docs commits)
- **Owner's decisions (2026-11-09):** build the run loop as an emitted-code
  change that keeps the generated-runtime ABI at 9, in this session, under
  byte-machine's own process. Inlining the callback step, which needs ABI 10,
  is later work.
- **Disposition (2026-11-09):** built as byte-machine's decision 0059 and
  released in 0.9.0 (PR #180, #181, tag `v0.9.0`). jsonparse regenerates on
  it in ADR-0026.

## The ask

A `dispatch` state whose transitions advance back to the state itself should
compile those transitions into a tight loop. The loop reads a byte, tests it
against the class of bytes that loop back, and steps on, until a byte leaves
the class or the input ends. That byte then goes where the state's
dispatch would have sent it.

Nothing else should change:
- not the source IR, the normalized IR, a fingerprint or the ABI literal 9;
- not the runtime, the interpreter or the verifier;
- not any outcome a caller can see: status, offsets, `pk`, errors, spans,
  need-input and resumption across feeds, pauses.

Only the emitted text changes, as it did in 0.8.0's digit fix. A parser
generated by 0.8.0 still loads and runs on the new runtime, so byte-machine's
other consumers need not regenerate. Doing so gains them the loop.

## Why

Plan M3's lever 2 is a run node for string bodies: long stretches of bytes
that only need checking. A string's body is one `dispatch` state that
advances to itself on 94 bytes. Each byte is a tail call back into the
state: a test against the input's end, a byte read, then the state's clauses
in byte order. A lowercase letter matches the sixth clause, after ten
comparisons.

This doesn't close M3's gaps. `events` trails yajl by 4× on `records-2k` and
4.30–4.65× on `escaped-string` (ADR-0025), and the loop moves neither, as
measured below. It speeds up long strings, as in `gsoc-2018` and `twitter`,
and may speed up HTTP's header values, which byte-machine's own benchmark
will show.

## The lowering prototyped

By hand, on jsonparse's generated parser. The shape to build is P1j, which
gives every qualifying state a loop:

```scheme
;; at library level, beside errs: a class of more than one range, as a
;; table shared by every state with that class; 1 for a byte that loops back
(define rc1 (quote #vu8(0 0 ... 1 1 0 1 ... 0)))

;; in the state's dispatch, each arm that advanced to itself,
;;   ((and (fx>=? b 35) (fx<=? b 91)) (%s76 (+ pos 1) 76 (+ off 1) (quote boundary)))
;; now enters the loop:
((and (fx>=? b 35) (fx<=? b 91)) (%r76 (fx+ pos 1) pos off))

;; beside the state:
(define (%r76 p pos0 off0)
  (if (fx<? p end)
      (let ((b (bytevector-u8-ref bv p)))
        (if (fx=? 1 (bytevector-u8-ref rc1 b))   ; one range: (and (fx>=? b 48) (fx<=? b 57))
            (%r76 (fx+ p 1) pos0 off0)
            (let ((pos p) (off (+ off0 (fx- p pos0))))
              (cond
                ;; the state's own clauses, but those that loop back
                ((and (fx>=? b 0) (fx<=? b 31)) (%s133 pos 133 off (quote byte)))
                ((fx=? b 34) (%s84 pos 84 off (quote byte)))
                ...
                (else (%s132 pos 132 off (quote byte)))))))
      (%s76 p 76 (+ off0 (fx- p pos0)) (quote boundary))))
```

- **The loop starts only after a first byte in the class.** A byte outside
  it pays nothing new. P1, which tested the class on entry to the state, made
  `poet` 8–9% slower: its text is 87% multibyte, so it re-entered the state
  every few bytes.
- **The loop dispatches the byte that ends it,** over the state's other
  clauses. Leaving through the state instead (P1g) read and tested that byte
  twice, which made the short runs of whitespace and digits slower: `citm`
  by 10–12%, `canada` by 5–8%.
- **At the end of the feed it enters the state itself,** whose code then
  handles need-input and `finish?` as now.
- **`off` is worked out once, when the loop ends,** from the bytes read. A
  position within one feed is a fixnum, since it indexes a bytevector, but a
  stream offset may not be, so it keeps generic `+`.

## Measured

Pinned to one performance core on the reference NUC (`ta6le`, Chez 10.4.1),
`bench/run.sps` on ADR-0023's eight files. Each run of a variant took turns
with `main`'s parser (A), two runs each. P1b, P1c, P1g, P1h, P1i and P1j
each passed twelve of jsonparse's suites: conformance, fuzz, parser, parser
API, yajl, machine, string, tree, property, allocation, easy and sequence.
P1d passed five of them, and P1 none on its own: P1b carries its change. On
the worst file, A's own runs moved by up to 4% between turns. Change in
`events` against A, as time a byte:

| file | A, ns a byte | P1c: strings only | P1g: all, leaving through the state | P1j: all, dispatching the last byte |
|:--|--:|--:|--:|--:|
| gsoc-2018 | 4.78, 4.78 | −42%, −43% | −39%, −40% | −41%, −41% |
| twitter | 4.37, 4.34 | −11%, −6% | 0%, −3% | −7%, −12% |
| poet | 3.65, 3.65 | −12%, −7% | −5%, −6% | −1%, −3% |
| escaped-string | 5.21, 5.23 | 0%, +1% | −4%, −4% | 0%, +3% |
| records-2k | 7.41, 7.41 | −1%, +1% | +6%, +5% | −2%, −1% |
| canada | 4.56, 4.55 | −4%, −3% | +8%, +5% | −2%, −4% |
| citm | 3.82, 3.82 | −5%, −2% | +12%, +10% | +2%, +2% |
| ints-40k | 7.30, 7.55 | −1%, +4% | +5%, +5% | +1%, +4% |

P1g's column comes from another rotation, against its own runs of A.

- **The class test is a table, unless the class is one range.** For the
  string's three ranges a 256-byte table beat range tests: P1c took 39–42%
  less time on `gsoc-2018` in another rotation, against 9–15% less with
  ranges (P1d). That is the reverse of 0050's finding for one dispatch: the
  loop runs the test on every byte, and one load costs less than up to six
  comparisons. For one range, the digits, a table was no better, and two
  comparisons need no table. Only the string's class was measured this way.
- **The emitted text grew 10%,** 92,635 bytes to 102,121, from the 14 loops'
  dispatch copies and two tables. P1c, two loops, grew 1%.
- **P1j slows no file by more than 4%,** but `citm` took 2% more time in
  both its runs, where A's own two runs were 0.06% apart. Its gains are on
  long runs of ASCII: `gsoc-2018`'s average 67 bytes and `twitter`'s 14.
  `records-2k`'s average 5 bytes. `escaped-string`'s average 29, between
  clusters of four escapes, and each escape costs far more than a byte of
  text. Neither M3 target moves.

## What byte-machine's Gate 0 should settle

- **Which states qualify:**
  - a `dispatch` state with at least one transition that advances to itself;
  - a state whose fallback advances to itself. Its class is then every byte
    no transition names. Measured on the normalized IR, chez-httparse's
    message parser has 24 states of the first kind and 3 of the second, and
    its url parser 5; jsonparse has 14 and none. (A first count by text read
    26 and 3.)
  - but not a state whose class is empty: one whose transitions name all 256
    bytes, none of them looping back, so its fallback is never taken. The
    review of byte-machine's build found that this rule, as first written
    here, made `render-machine` raise on such a machine, which 0.8.0 renders.
- **Whether every qualifying state should loop,** as P1j does, measured on
  its own benchmark against decision 0048's thresholds, and on chez-httparse's
  parsers.
- **The emitted size,** against `§28`'s limit on generated code.
- **What catches a wrong loop:** a class one byte too wide or too narrow, an
  `off` wrong by the bytes read, a loop that runs past `end`, an exit byte
  sent to the wrong clause, and a `pk` left as `byte`. Each needs a test that
  fails.

## Not asked

- **A new node kind.** The plan's lever 2 named one. The loop needs none,
  because it is a property of an existing state.
- **An ABI change, or unsafe operations** (ADR-0003 keeps the generated
  parser `(rnrs)`-only).
- **The callback step inlined.** Prototyped beside this (P3), it cut
  `records-2k` 12–13% and `canada` 9–10%. It reaches into the parser's slots,
  so it needs ABI 10 and every consumer regenerated. It waits for its own
  slice, with M2 decided first, so one bump carries both (ADR-0004).

## After the release

jsonparse moves `vendor/byte-machine` and its Akku floor to the release,
regenerates `(generated jsonparse)`, and measures `make bench` against
`main`, taking turns. That record is ADR-0026.
