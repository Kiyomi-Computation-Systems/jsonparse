# byte-machine JSON — project plan

Date: 2026-10-03
Status: proposal. Milestone 0 (prototype and measurement) is done; nothing else has started.
Owner: d$ / Kiyomi Computation Systems

## 1. Goal

Build a YAJL-class JSON library for Chez Scheme whose parser is generated by
byte-machine. YAJL-class means:

- push-based, incremental input;
- an event (SAX) interface, with a tree (DOM) interface layered on top;
- strict RFC 8259 conformance, with explicit leniency options;
- byte offsets on errors;
- no per-byte allocation.

Along the way, decide whether byte-machine itself should grow a primitive for
nested structure. That primitive is the one thing JSON needs that byte-machine
does not have today.

The JSON library follows the pattern byte-machine already set for HTTP:
byte-machine stays a generator, and the parser lives in a consumer project (like
chez-httparse).

## 2. Findings from Milestone 0

A prototype grammar (Appendix A, 316 lines, 131 nodes) was built using only the
public `(byte-machine graph)` API at v0.7.0. It passes the verifier and emits an
89 KB generated library. Re-emission is deterministic: the same fingerprint every
time.

**Conformance, JSONTestSuite `test_parsing` (318 files):**

| | `y_` must accept (95) | `n_` must reject (188) | `i_` implementation-defined (35) |
|---|---|---|---|
| byte-machine prototype | **95 / 95** | **188 / 188** | accepts 11 (the huge-number and 500-deep cases), rejects 24 |
| chez-json | 91 / 95 | 143 / 186 (2 skipped) | accepts 22, rejects 13 |

- **Chunking invariance.** Every accepted byte-machine case produces an `equal?`
  DOM when fed whole and when fed in chunks of 1, 2, 3 and 7 bytes.
- **What chez-json accepts that it shouldn't (43 cases):**
  - stray, doubled and trailing commas;
  - `2.`, `-2.`, `1.0e`, `- 1`;
  - unescaped control characters and tabs in strings;
  - comments;
  - trailing garbage;
  - unmatched `]` / `}`.
- **What chez-json rejects that it shouldn't (4 cases):** a lone top-level number
  (EOF ends a number) and `0e1` / `0e+1`.

**Throughput** (mean per run: 10 runs, chez-json 2; YAJL 200; MB/s of input):

| Input | YAJL 2.1.1 (null callbacks) | byte-machine, events only | byte-machine + DOM | chez-json (DOM) |
|---|---|---|---|---|
| `ints-40k` (229 KB, 40k-element array) | 280 | **105** | 28.5 | 0.06 (4.15 s, 14 GB allocated) |
| `records-2k` (320 KB, 2k small objects) | 353 | **107** | 38.9 | 18.3 |
| `escaped-string` (245 KB, one string with `\n`, `é`, surrogate pairs) | 1746 | **132** | 74.8 | 0.46 |

How the numbers were measured:

- **Environment:** x86_64 Xeon 2.1 GHz, Linux, Chez Scheme **9.5.8**, which is
  below byte-machine's stated 10.4.1 floor. Libraries ran in source mode at the
  default safe optimize level.
- **YAJL:** built `-O2`, UTF-8 validation on.
- **"Events only"** means the parser plus the minimal stack consumer that
  `context` needs. The bytes in spans are delivered to no one.

What the numbers say:

- On structure-heavy input, the parser alone is within **~3×** of YAJL.
- On string-heavy input it is about **13×** behind. YAJL's lexer runs a tight
  table loop over string bodies; byte-machine pays one state dispatch per byte.
  That is the main performance target (§5, M3).
- The DOM consumer is 2–4× slower than the parser alone. Most of that is a fresh
  `bytevector-output-port` per string or number, which is a consumer problem and
  not a parser problem.

**Semantics observed:**

- `null`, `[]` and `{}` are distinct (`null`, `#()`, `()`).
- Key order and duplicate keys are preserved.
- Bignums come for free.
- `😀` decodes to 😀.
- `{"a": [1, 2,, 3]}` reports `unexpected-byte` at offset 12.
- `[1] x` reports `trailing-garbage` at offset 4.
- Depth 512 is accepted; depth 513 reports `nesting-too-deep` at offset 513.
- With the settable `mode` field set to 1, `1 2 3 4` parses as four top-level
  values.

## 3. Architecture comparison

| | chez-json | YAJL | byte-machine JSON (prototype) |
|---|---|---|---|
| Origin | port of guile-json 0.5 (2013) | C, hand-written | generated from a verified machine |
| Input unit | `char` from a textual port | byte buffer | bytevector slice `[start,end)` |
| Control | recursive descent | lexer + pushdown automaton (byte stack) | DFA + depth counter; stack held by the consumer through a decision callback |
| Incremental | no; blocks on the port | yes; partial tokens buffered across chunks | yes; resumable at any byte, plus pause/resume with a reason |
| Output | fixed DOM (hashtables, lists) | SAX callbacks; `yajl_tree` is optional | events and spans; a DOM is one fold over them |
| Strings | `string-append` per segment | zero-copy pointer when unescaped | span slices delivered in place, never retained |
| Numbers | `string->number`; malformed input becomes `#f` | `long long` / `double`, or the raw text | raw text span; exact bignums |
| Errors | `(error 'json-invalid …)`, no position | byte offset + context | structured record: code, offset, node, and the abandoned span |
| UTF-8 | delegated to the port transcoder | validated (configurable) | validated in-machine (the 9-state DFA) |
| Surrogates | decoded independently, so broken | correct | pairing enforced by the machine |
| Depth limit | none (stack depth) | none built in | field, checked in-machine (512) |
| Options | none | comments, multiple values, partial values, trailing garbage, skip validation | multiple values (settable `mode` bit); the rest is the M4 plan |

Appendix B lists chez-json's defects.

## 4. Design of the prototype

### 4.1 Event model

| Callback | Kind | Meaning |
|---|---|---|
| `object-start` `object-end` `array-start` `array-end` | event | container boundaries |
| `key-start` `key-end` `string-start` `string-end` | event | string boundaries, separated by role |
| `chars-data` | span-data | raw, already-validated UTF-8 bytes between escapes |
| `escape` | event | one UTF-16 code unit, in field `cp`; a high surrogate is always followed by its low half |
| `number-data` / `number-end` | span-data / span-complete | the number's text |
| `true` `false` `null` | event | literals |
| `context` | **decision** → `object` \| `array` | asked after a value whenever depth > 0 |

The fields are:

- `depth` (uint16), checked against `max-depth`;
- `cp` (uint16), the escape code unit;
- `mode` (uint8, settable), with bit 0 meaning "allow multiple values".

### 4.2 What the machine owns, and what the consumer owns

The verified machine owns everything except one decision:

- the full number grammar;
- string scanning;
- UTF-8 well-formedness, including overlongs, surrogates encoded as UTF-8, and
  values above U+10FFFF;
- control-character rejection;
- escape decoding, with `\uXXXX` read as four chained `integer-accumulate`
  nodes;
- surrogate pairing, using `range` branches;
- the depth limit;
- trailing-garbage rejection;
- EOF handling, so a top-level number can end the document.

The one decision left to the consumer is whether the enclosing container is an
object or an array. The consumer answers it from a stack it keeps in
`user-context` (§4.3).

### 4.3 Why there is a `context` callback (the nesting problem)

JSON is not regular. After a value, the next legal byte depends on the
enclosing container: `,` then a key, or `}`, in an object; `,` then a value, or
`]`, in an array. byte-machine is a DFA plus fixed-width counters, and its plan
lists context-free grammars as a non-goal.

The prototype therefore uses **option 1**:

1. `[` and `{` fire events.
2. The consumer pushes onto a stack in `user-context`.
3. After each value at depth > 0, the decision callback returns the top of that
   stack.
4. The machine branches to `obj-next` or `arr-next`.

The costs:

- one callback round trip per value inside a container;
- correct nesting now depends on unverified consumer code. A buggy `context`
  answer turns `[1}` into "valid". The machine still guarantees balance by
  count, through `depth`.
- `context` must be bound even by consumers that only want events. It is a
  required callback, and `make-parser` refuses an unbound one.

### 4.4 Generator style

The key and value string sub-machines (≈45 nodes each) come from one function
parameterised by role, start event, end event and continuation. Containers come
from one function per kind. The grammar is ordinary data built by pure
functions, which is what byte-machine's builder API was designed for.

### 4.5 What the verifier caught while the prototype was written

These are useful as evidence that the verifier earns its keep:

- **`overlapping-cases`:** the ASCII run range included `"` and `\`.
- **`zero-progress-cycle` / `eof-zero-progress-cycle`:** the decision callback's
  pause continuation pointed back at itself.
- **`invalid-name`:** `lone-lo?` is not a portable name.

## 5. Plan

### M0 — Prototype and measurement (done, 2026-10-03)

The deliverables are in `prototype/` next to this file: the grammar, the DOM
consumer, the generator, the JSONTestSuite runner, the benchmarks, and the YAJL
benchmark harness.

### M1 — The JSON library, on byte-machine as it is (option 1)

Create a consumer repository (working name `chez-json-bm`) shaped like
chez-httparse. It contains:

- the grammar and the generator;
- the generated `.sls`, checked in with its fingerprint;
- `(… events)`, a handler API with a record of procedures in YAJL order;
- `(… tree)`, a DOM fold. Settle the representation: `null` symbol versus a
  unique object; alist versus an ordered map for objects; vectors for arrays.
- `(… string)`, a reusable string and number assembler with one growable buffer
  per parser, not one port per token. This is the main source of the 2–4× DOM
  overhead in §2.

Test lanes:

- JSONTestSuite `y_`/`n_` as a gate;
- `i_` results pinned in a golden file;
- chunking invariance over every split point for small inputs, plus random
  schedules for large ones;
- a differential lane, byte-machine's interpreter versus generated code, using
  the project's existing harness;
- property tests from a JSON generator, checking that serialize → parse is the
  identity.

**Exit criteria:** 100% of `y_` and `n_`; chunk-invariant; no allocation slope in
events-only mode (decision 0040's audit method); documented API.

### M2 — byte-machine: nesting as a verified primitive (option 3)

Write a decision record first. The proposal is a **bit-stack** expressed as field
operations on an existing `uint` field, rather than a new node kind:

- new field operations `push-bit b` (`v := (v << 1) | b`, checked: errors when the
  top bit is set) and `pop-bit` (`v := v >> 1`, checked: errors at 1);
- a sentinel-1 encoding, so emptiness is `v = 1` (an `equal` branch) and the top
  of the stack is `mask-any 1`;
- capacity 63 levels per 64-bit field. Deeper nesting chains a second field, or
  rides on the depth counter plus a consumer stack beyond 63.

Why this shape:

- It stays inside byte-machine's model: fixed-width, checked, allocation-free,
  and inspectable.
- It needs no new verifier family. The overflow edge already exists for checked
  operations.
- It turns `context` from a required decision callback into two field
  operations and one branch per value.

**Scope decision for d$:** this widens byte-machine from "regular plus counters"
to "bounded pushdown". It should be recorded as an amendment to §4's non-goals,
not slipped in. The alternative is to keep option 1 permanently and document
that nesting is a consumer obligation.

Work items:

- the decision record;
- `field-operations` grows by two;
- the interpreter, normalizer, emitter and runtime;
- an ABI bump (9 → 10);
- the property generator learns the new operations;
- the mutation suite gets pins for both;
- a private JSON fixture in byte-machine, mirroring the HTTP fixture, that proves
  the primitive on a real grammar.

**Exit criteria:**

- the JSON grammar drops `context`, and its conformance is unchanged;
- `[1}` is rejected by the machine with no consumer involvement;
- the events-only throughput on `records-2k` improves, or the decision record
  says why it didn't.

### M3 — Performance: string bodies and number fast path

The measured gap is about 13× on string bodies. The levers, in the order to try
them:

1. **Measure first.** Run the benchmarks on Chez ≥ 10.4.1 in the AOT lane on
   `tarm64osx`, so the numbers are comparable with byte-machine's own baseline.
   9.5.8 in source mode is not representative.
2. **A run node kind.** "Consume while the byte is in class C" as one
   node: llparse's span-consume loop, or YAJL's string scan. It lowers to a tight
   index loop with no per-byte state dispatch. The verifier treats it as a byte
   dispatch whose matching case returns to itself. It also helps HTTP header
   values. This needs a decision record, because it is a new node kind and an
   ABI bump.
3. **Unsafe bytevector access in emitted code.** The plan's decision 10 admits
   Chez-specific emission "only when reproducible compiled benchmarks demonstrate
   a material need". The run node gives a contained place to test that.
4. **Number fast path.** `integer-accumulate` into a `uint 64` in parallel with
   the span, with overflow falling back to the text. This needs one more field
   and an event that tells the consumer which value to use.

**Exit criteria:**

- events-only throughput within **2×** of YAJL on `records-2k`, and within **4×**
  on `escaped-string`, on the reference cell;
- the byte-machine benchmark baseline is updated.

### M4 — YAJL feature parity and serializer

- **Options as settable `mode` bits,** using decision 0047's mechanism:
  - allow multiple values (done);
  - allow comments (`//` and `/* */` states, gated by a `mask-any` branch at each
    whitespace site);
  - allow trailing garbage;
  - allow partial values (EOF routes check a bit before erroring);
  - skip UTF-8 validation (a second string body that bypasses the UTF-8 states).
- **Cancel and pause:** map YAJL's "callback returns 0" onto
  `make-callback-failure`. byte-machine's pause is a superset of what YAJL
  offers.
- **Serializer** (`yajl_gen` equivalent): a pure fold from DOM or events to
  bytes, with a beautify option, escaping, and validated nesting. It does not
  need byte-machine.

**Exit criteria:** an option matrix tested against JSONTestSuite, so each option
flips only the cases it should; serializer round-trip property tests.

### M5 — Release

- versioning tied to the byte-machine ABI;
- Guix package, following the existing Creating Guix Packages work;
- documentation, including a "migrating from chez-json" note (the
  `null`/`'()` change and the hashtable → alist change).

## 6. Risks

| Risk | Mitigation |
|---|---|
| The M2 scope change is rejected, so nesting stays a consumer obligation forever | M1 ships on option 1 regardless. The `context` contract is documented, and the tree builder is the reference implementation that tests it. |
| The run node (M3) doesn't close the string gap enough | Ship anyway. 130 MB/s is already more than 280× chez-json on escaped strings. Revisit with unsafe ops under decision 10. |
| The callback per value dominates object-heavy input | M2 removes it. Measure before and after on `records-2k`. |
| Generated-code size grows with options (each option duplicates sub-machines) | Track `generated-source-size-bytes`, as byte-machine's baseline already does. Prefer branch gates over duplicated states. |
| The Chez 9.5.8 numbers mislead | Re-measure on the supported floor first (M3 step 1) before setting targets in stone. |

## 7. Open questions for d$

1. **Repository:** a new consumer repo (recommended, matches chez-httparse) or a
   `contrib/` inside byte-machine?
2. **M2:** amend byte-machine's non-goals to admit a bounded bit-stack, or keep
   nesting in callbacks?
3. **DOM representation:** alist or ordered hashtable for objects? Should `null`
   be a symbol or a unique sentinel?
4. **Does chez-json's API need a compatibility shim** (`json->scm`,
   `json-string->scm`) for existing callers?
5. **Depth limit default:** 512 (as in the prototype), 1024, or settable at
   construction?

## Appendix A — Prototype grammar (`prototype/bmjson/grammar.sls`)

```scheme
;;; (bmjson grammar) -- prototype JSON (RFC 8259) machine for byte-machine 0.7.
;;;
;;; Built only through the public (byte-machine graph) API. The machine is
;;; regular plus one counter; nesting (object vs array) is resolved by the
;;; `context` DECISION callback, whose stack lives in the consumer's
;;; user-context ("option 1" in the plan). Everything else -- the number
;;; grammar, string scanning, UTF-8 validation, escape decoding, surrogate
;;; pairing, the depth limit, trailing-garbage rejection -- is in the verified
;;; machine.
;;;
;;; Event stream (all optional except `context`):
;;;   object-start object-end array-start array-end          (event)
;;;   key-start key-end string-start string-end              (event)
;;;   chars-data   (span-data)  raw, already-validated UTF-8 between escapes
;;;   escape       (event)      one UTF-16 code unit in field `cp`; a high
;;;                             surrogate is ALWAYS followed by its low half
;;;   number-data / number-end  (span-data / span-complete)  the number's text
;;;   true false null           (event)
;;;   context      (decision)   -> object | array; asked only at depth > 0
;;;
;;; Fields: depth (uint16, limit MAX-DEPTH), cp (uint16, escape code unit),
;;;         mode (uint8, settable; bit 0 = allow multiple top-level values).
(library (bmjson grammar)
  (export json-machine max-depth mode-allow-multiple)
  (import (rnrs) (byte-machine graph))

  (define max-depth 512)
  (define mode-allow-multiple 1)

  ;; --- small builders ---------------------------------------------------------
  (define (b c) (if (char? c) (char->integer c) c))
  (define (byte= c) (make-exact-byte-matcher (b c)))
  (define (one-of . cs) (make-byte-set-matcher (map b cs)))
  (define (range lo hi) (make-byte-range-matcher (b lo) (b hi)))
  (define (adv t) (make-edge t 'advance))
  (define (re t) (make-edge t 'reexecute))
  (define (case* m e) (make-byte-case m e #f))
  (define ws (one-of #\space #\tab #\newline #\return))
  (define digit (range #\0 #\9))
  (define (dispatch name cases fallback . eof)
    (make-byte-dispatch-node name cases fallback (if (null? eof) #f (car eof)) #f))
  (define (cb name callback next)
    (make-callback-node name callback next '() next #f))
  (define (sym . parts)
    (string->symbol
     (apply string-append
            (map (lambda (p) (if (symbol? p) (symbol->string p) p)) parts))))

  ;; --- declarations -------------------------------------------------------------
  (define (event name) (make-callback-declaration name 'event #f '() #f #f))

  (define callbacks
    (append
     (map event '(object-start object-end array-start array-end
                  key-start key-end string-start string-end
                  escape true false null))
     (list (make-callback-declaration 'chars-data 'span-data #f '() #f #f)
           (make-callback-declaration 'number-data 'span-data #f '() #f #f)
           (make-callback-declaration 'number-end 'span-complete #f '() #f #f)
           (make-callback-declaration 'context 'decision #t '(object array) #f #f))))

  (define spans
    (list (make-span-declaration 'chars 'chars-data #f #f)
          (make-span-declaration 'number 'number-data 'number-end #f)))

  (define field-decls
    (list (make-uint-field 'depth 16 0 #f)
          (make-uint-field 'cp 16 0 #f)
          (make-uint-field 'mode 8 0 #t #f)))

  (define errors
    (list (make-error-declaration 'eof 'unexpected-eof "unexpected end of input" #f)
          (make-error-declaration 'unexpected 'unexpected-byte "unexpected byte" #f)
          (make-error-declaration 'bad-number 'invalid-number "malformed number" #f)
          (make-error-declaration 'bad-escape 'invalid-escape "malformed escape" #f)
          (make-error-declaration 'bad-surrogate 'invalid-surrogate "unpaired surrogate" #f)
          (make-error-declaration 'bad-utf8 'invalid-utf8 "invalid UTF-8" #f)
          (make-error-declaration 'control-char 'control-character "unescaped control character" #f)
          (make-error-declaration 'too-deep 'nesting-too-deep "nesting exceeds limit" #f)
          (make-error-declaration 'trailing 'trailing-garbage "data after the top-level value" #f)
          (make-error-declaration 'no-context 'missing-context "context callback answered continue" #f)))

  (define error-nodes
    (list (make-error-node 'e-unexpected 'unexpected #f)
          (make-error-node 'e-number 'bad-number #f)
          (make-error-node 'e-escape 'bad-escape #f)
          (make-error-node 'e-surrogate 'bad-surrogate #f)
          (make-error-node 'e-utf8 'bad-utf8 #f)
          (make-error-node 'e-control 'control-char #f)
          (make-error-node 'e-deep 'too-deep #f)
          (make-error-node 'e-trailing 'trailing #f)
          (make-error-node 'e-context 'no-context #f)
          (make-error-node 'e-eof 'eof #f)))

  ;; --- values -------------------------------------------------------------------
  (define value-nodes
    (list
     (dispatch 'value
       (list (case* ws (adv 'value))
             (case* (byte= #\{) (adv 'obj-open))
             (case* (byte= #\[) (adv 'arr-open))
             (case* (byte= #\") (adv 'str-begin))
             (case* (byte= #\-) (re 'num-begin))
             (case* digit (re 'num-begin))
             (case* (one-of #\t #\f #\n) (re 'literal)))
       (re 'e-unexpected))
     (make-sequence-dispatch-node 'literal
       (list (make-sequence-case (ascii-bytes "true") 'lit-true #f)
             (make-sequence-case (ascii-bytes "false") 'lit-false #f)
             (make-sequence-case (ascii-bytes "null") 'lit-null #f))
       (re 'e-unexpected) #f #f)
     (cb 'lit-true 'true 'after-value)
     (cb 'lit-false 'false 'after-value)
     (cb 'lit-null 'null 'after-value)))

  ;; --- containers -----------------------------------------------------------------
  ;; open: depth+1, enforce the limit, announce.  close: depth-1, announce.
  (define (container-nodes kind open-cb close-cb first-node)
    (let ((open (sym kind "-open")) (check (sym kind "-check"))
          (announce (sym kind "-announce")) (close (sym kind "-close"))
          (closed (sym kind "-closed")))
      (list
       (make-field-action-node open 'increment '(depth) check 'e-deep #f)
       (make-field-branch-node check 'range (list 'depth 1 max-depth) announce 'e-deep #f)
       (cb announce open-cb first-node)
       (make-field-action-node close 'decrement '(depth) closed 'e-deep #f)
       (cb closed close-cb 'after-value))))

  (define object-nodes
    (append
     (container-nodes 'obj 'object-start 'object-end 'obj-first)
     (list
      (dispatch 'obj-first
        (list (case* ws (adv 'obj-first))
              (case* (byte= #\") (adv 'key-begin))
              (case* (byte= #\}) (adv 'obj-close)))
        (re 'e-unexpected))
      (dispatch 'obj-next
        (list (case* ws (adv 'obj-next))
              (case* (byte= #\,) (adv 'obj-key))
              (case* (byte= #\}) (adv 'obj-close)))
        (re 'e-unexpected))
      (dispatch 'obj-key
        (list (case* ws (adv 'obj-key))
              (case* (byte= #\") (adv 'key-begin)))
        (re 'e-unexpected))
      (dispatch 'colon
        (list (case* ws (adv 'colon))
              (case* (byte= #\:) (adv 'value)))
        (re 'e-unexpected)))))

  (define array-nodes
    (append
     (container-nodes 'arr 'array-start 'array-end 'arr-first)
     (list
      (dispatch 'arr-first
        (list (case* ws (adv 'arr-first))
              (case* (byte= #\]) (adv 'arr-close)))
        (re 'value))
      (dispatch 'arr-next
        (list (case* ws (adv 'arr-next))
              (case* (byte= #\,) (adv 'value))
              (case* (byte= #\]) (adv 'arr-close)))
        (re 'e-unexpected)))))

  ;; After any value: at depth 0 we are done; otherwise ask the consumer.
  (define after-value-nodes
    (list
     (make-field-branch-node 'after-value 'zero '(depth) 'top-done 'ask-context #f)
     (make-callback-node 'ask-context 'context 'e-context
                         '((object obj-next) (array arr-next)) 'e-context #f)
     (dispatch 'top-done
       (list (case* ws (adv 'top-done)))
       (re 'top-more) 'done)
     (make-field-branch-node 'top-more 'mask-any (list 'mode mode-allow-multiple)
                             'value 'e-trailing #f)
     (make-finish-node 'done #f)))

  ;; --- strings ----------------------------------------------------------------------
  ;; One sub-machine per role (key / string), generated from the same function:
  ;; the roles differ only in their start/end events and where they go after.
  (define (string-nodes role start-cb end-cb after)
    (define (n . parts) (apply sym role "-" parts))
    (define cont (range #x80 #xBF))
    (define (need k next)                ; k continuation bytes, then `next`
      (dispatch (n "u" (number->string k))
        (list (case* cont (adv (if (= k 1) next (n "u" (number->string (- k 1)))))))
        (re 'e-utf8)))
    (define (simple-escape ch code)
      (list (case* (byte= ch) (adv (n "esc-" (number->string code))))))
    (define escapes
      '((#\" . #x22) (#\\ . #x5C) (#\/ . #x2F) (#\b . #x08)
        (#\f . #x0C) (#\n . #x0A) (#\r . #x0D) (#\t . #x09)))
    (define (hex4 prefix done)          ; four hex digits into `cp`, then `done`
      (let loop ((i 1) (acc '()))
        (if (> i 4)
            (reverse acc)
            (loop (+ i 1)
                  (cons (make-integer-accumulate-node
                         (n prefix (number->string i)) 'cp 16
                         (if (= i 4) done (n prefix (number->string (+ i 1))))
                         (re 'e-escape) 'e-escape #f #f)
                        acc)))))
    (append
     (list
      (cb (n "begin") start-cb (n "run"))
      (make-span-start-node (n "run") 'chars (n "chars") #f)
      ;; the hot loop: ASCII text stays here
      (dispatch (n "chars")
        (list (case* (byte= #\") (re (n "end-run")))
              (case* (byte= #\\) (re (n "esc-run")))
              (case* (range #x00 #x1F) (re 'e-control))
              (case* (range #x20 #x21) (adv (n "chars")))
              (case* (range #x23 #x5B) (adv (n "chars")))
              (case* (range #x5D #x7F) (adv (n "chars")))
              (case* (range #xC2 #xDF) (adv (n "u1")))
              (case* (byte= #xE0) (adv (n "e0")))
              (case* (one-of #xE1 #xE2 #xE3 #xE4 #xE5 #xE6 #xE7 #xE8 #xE9 #xEA #xEB #xEC #xEE #xEF)
                     (adv (n "u2")))
              (case* (byte= #xED) (adv (n "ed")))
              (case* (byte= #xF0) (adv (n "f0")))
              (case* (range #xF1 #xF3) (adv (n "u3")))
              (case* (byte= #xF4) (adv (n "f4"))))
        (re 'e-utf8))
      (need 1 (n "chars")) (need 2 (n "chars")) (need 3 (n "chars"))
      (dispatch (n "e0") (list (case* (range #xA0 #xBF) (adv (n "u1")))) (re 'e-utf8))
      (dispatch (n "ed") (list (case* (range #x80 #x9F) (adv (n "u1")))) (re 'e-utf8))
      (dispatch (n "f0") (list (case* (range #x90 #xBF) (adv (n "u2")))) (re 'e-utf8))
      (dispatch (n "f4") (list (case* (range #x80 #x8F) (adv (n "u2")))) (re 'e-utf8))
      ;; closing quote: close the run, consume the quote, announce
      (make-span-end-node (n "end-run") 'chars (n "quote") #f)
      (dispatch (n "quote") (list (case* (byte= #\") (adv (n "end")))) (re 'e-unexpected))
      (cb (n "end") end-cb after)
      ;; backslash: close the run, consume it, decode the escape
      (make-span-end-node (n "esc-run") 'chars (n "slash") #f)
      (dispatch (n "slash") (list (case* (byte= #\\) (adv (n "esc")))) (re 'e-unexpected))
      (dispatch (n "esc")
        (append (apply append (map (lambda (e) (simple-escape (car e) (cdr e))) escapes))
                (list (case* (byte= #\u) (adv (n "uclear")))))
        (re 'e-escape)))
     ;; simple escapes: store the code unit, announce, resume the run
     (apply append
       (map (lambda (e)
              (let ((code (cdr e)))
                (list (make-field-action-node (n "esc-" (number->string code)) 'store
                                              (list 'cp code) (n "emit") #f #f))))
            escapes))
     (list
      (cb (n "emit") 'escape (n "run"))
      ;; \uXXXX
      (make-field-action-node (n "uclear") 'clear '(cp) (n "h1") #f #f))
     (hex4 "h" (n "classify"))
     (list
      (make-field-branch-node (n "classify") 'range '(cp #xD800 #xDBFF)
                              (n "emit-hi") (n "lone-lo") #f)
      (make-field-branch-node (n "lone-lo") 'range '(cp #xDC00 #xDFFF)
                              'e-surrogate (n "emit") #f)
      ;; a high surrogate must be followed by \u + a low surrogate
      (cb (n "emit-hi") 'escape (n "lo-slash"))
      (dispatch (n "lo-slash") (list (case* (byte= #\\) (adv (n "lo-u")))) (re 'e-surrogate))
      (dispatch (n "lo-u") (list (case* (byte= #\u) (adv (n "lo-clear")))) (re 'e-surrogate))
      (make-field-action-node (n "lo-clear") 'clear '(cp) (n "l1") #f #f))
     (hex4 "l" (n "lo-check"))
     (list
      (make-field-branch-node (n "lo-check") 'range '(cp #xDC00 #xDFFF)
                              (n "emit") 'e-surrogate #f))))

  ;; --- numbers ----------------------------------------------------------------------
  ;; -?(0|[1-9][0-9]*)(\.[0-9]+)?([eE][+-]?[0-9]+)?  -- the span carries the text.
  ;; A number can end the document, so its accepting states route EOF through
  ;; the span end and the depth check to `done`.
  (define number-nodes
    (let ((end (re 'num-end)) (bad (re 'e-number)))
      (list
       (make-span-start-node 'num-begin 'number 'num-sign #f)
       (dispatch 'num-sign
         (list (case* (byte= #\-) (adv 'num-lead))
               (case* (byte= #\0) (adv 'num-zero))
               (case* (range #\1 #\9) (adv 'num-int)))
         bad)
       (dispatch 'num-lead
         (list (case* (byte= #\0) (adv 'num-zero))
               (case* (range #\1 #\9) (adv 'num-int)))
         bad)
       (dispatch 'num-zero
         (list (case* (byte= #\.) (adv 'num-frac0))
               (case* (one-of #\e #\E) (adv 'num-exp0))
               (case* digit bad))
         end 'num-eof)
       (dispatch 'num-int
         (list (case* digit (adv 'num-int))
               (case* (byte= #\.) (adv 'num-frac0))
               (case* (one-of #\e #\E) (adv 'num-exp0)))
         end 'num-eof)
       (dispatch 'num-frac0 (list (case* digit (adv 'num-frac))) bad)
       (dispatch 'num-frac
         (list (case* digit (adv 'num-frac))
               (case* (one-of #\e #\E) (adv 'num-exp0)))
         end 'num-eof)
       (dispatch 'num-exp0
         (list (case* (one-of #\+ #\-) (adv 'num-exp1))
               (case* digit (adv 'num-exp)))
         bad)
       (dispatch 'num-exp1 (list (case* digit (adv 'num-exp))) bad)
       (dispatch 'num-exp (list (case* digit (adv 'num-exp))) end 'num-eof)
       (make-span-end-node 'num-end 'number 'after-value #f)
       (make-span-end-node 'num-eof 'number 'num-eof-depth #f)
       (make-field-branch-node 'num-eof-depth 'zero '(depth) 'done 'e-eof #f))))

  (define json-machine
    (make-machine 'json 'value field-decls callbacks spans errors
      (append value-nodes object-nodes array-nodes after-value-nodes
              (string-nodes 'key 'key-start 'key-end 'colon)
              (string-nodes 'str 'string-start 'string-end 'after-value)
              number-nodes error-nodes)
      'eof #f)))
```

## Appendix B — chez-json defects (verified under Chez 9.5.8)

chez-json is a 2016 fork of guile-json 0.5. Its README claims strict compliance
with json.org; it does not comply.

| Input | Result | Defect |
|---|---|---|
| `[]` and `null` | both `()` | Empty array and null are indistinguishable. This is a data-model bug that can't be fixed without an API break. |
| `"--5 "`, `"- "` | `#f` | `string->number` fails silently, so a malformed number becomes `false`. |
| `123` at EOF | error | A number must be followed by a delimiter, so a lone top-level number is rejected. |
| `[1,,,2]`, `[,1,]`, `{,"a":1,}` | accepted | Commas are skipped like whitespace. |
| `[1] garbage` | `(1)` | No trailing-input check. |
| `1.e5` | `100000.0` | The dangling `.` is silently dropped. |
| `"😀"` | `"��"` | Each `\uXXXX` is decoded alone, so everything outside the BMP is lost. |
| 40,000-element array | 4.0 s, 14 GB allocated | `read-array` uses `(append values (list value))`, which is O(n²). Strings and numbers also grow by `string-append`. |
| any error | `(error 'json-invalid "json invalid" parser)` | No position, no cause. |
| objects | `equal?` hashtable | Key order is lost; duplicate keys keep the last value. |
